# 统一仓库与家庭认证

日期：2026-10-22。状态：已实现后的决策补录，未完成独立审查；不表示存在事前 Superpowers 审批记录。

## 背景

原有 Go 后端与原生小程序位于两个目录。用户要求整理到同一个私有 Git 仓库和本地 cost 目录，先完成微信登录，再考虑云端与正式发布。原版依赖开发令牌，没有用户和成员权限。

## 决定

1. 使用同一个仓库，backend/ 和 miniprogram/ 保留各自运行边界，统一说明和版本管理。
2. 保留 Go、MySQL 和原生小程序，复用已有记账、统计和预算实现。
3. 使用微信 code 在服务端验证身份，签发自有随机会话；登录与加入家庭分离。
4. 当前一个部署服务一个家庭，保留账本 ID=1；家庭成员共享读取，普通成员只编辑自己的记录，管理员管理预算和成员。
5. 首次管理员需要初始化密钥；其他成员通过一次性、24 小时有效的邀请码加入。
6. 旧账单保留，新增创建者字段为空；管理员维护历史账单。使用显式、可重入的版本迁移。

## 备选方案与取舍

- 继续前后端双仓库：可独立发布，但增加同一功能接口与文档同步成本；本阶段采用统一仓库。
- 改用云函数或重写后端：可以减少部分服务器运维，但会扩大当前改造范围；先沿用 Go 和 MySQL，云方案留待后续选择。
- 共用固定令牌：无法辨认成员和按创建者限制操作，不适合家庭共享。
- 首次微信登录自动成为管理员：有被其他账号抢先绑定的风险；改为持有初始化密钥才能绑定。
- 多家庭与个人账本：需要完整租户边界和归属设计，本阶段不实现。

这些是对已实现选择的说明，不代表所有备选方案曾在实施前经过正式评审。

## 影响

后端需配置 AppID/AppSecret，真实联调依赖微信开发者账号。成员移除后每次请求重新检查身份，已有账单保留。密钥只在本地忽略配置或服务端环境中保存。云端 HTTPS、代理下限流、备份恢复演练及真机多人验证仍需后续完成。
