# 测试与文档变更只检查、不部署（设计补录）

用户要求沿用 Resume Do 已确认的规则，完成验证后提交并推送。本记录在实现后补录，不代表事前设计审批；本环境未找到仓库引用的 Superpowers 技能包，不能声称完整执行了该技能流程。

## 目标与边界

- 保留现有 Go/MySQL、小程序、部署脚本与工作流检查，不通过跳过整个工作流来阻止部署。
- 独立 plan job 根据本次 push 的 before SHA 与 HEAD 判断部署资格。PR 使用目标分支的 merge-base，但部署 job 仍拒绝 PR。
- 文档、README、约定目录中的测试/夹具、Go `_test.go` 与 JS/TS `.test`/`.spec` 文件、CI 规划配置只检查。
- 运行代码、依赖、数据库迁移、部署输入及未知路径仍允许按原流程部署；移动运行代码到测试目录仍视为删除运行代码，不能绕过发布判断。
- 缺失或无效 before SHA 时默认只检查，手动 `full=true` 是明确部署覆盖选项。
- 不修改业务接口、身份认证、账本模型、生产配置或服务器；不修改 Git 历史。

## 实现与风险

`scripts/plan-ci.py` 输出 `deployment_required`。checks job 保持原样；deploy job 同时依赖 checks 与 plan，并要求该输出为 true。Git diff 使用 `--no-renames -z`，涵盖新增、删除、重命名及含空白的路径。

测试目录和文件名采用明确约定，不将整个 fixtures 目录名称普遍视为测试，避免运行时样例误归类。今后若业务代码开始导入测试目录，应调整该边界。

## 验收

实际 Git 临时仓库回归覆盖：测试/文档混合推送、删除夹具、运行代码改动、运行代码移至测试目录、PR merge-base、缺失/无效 before、手动全量及 GitHub 输出字符串。工作流语法与现有部署失败回归必须通过；推送后核对 Actions 检查成功且部署跳过。
