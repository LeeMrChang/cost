# 微信用户头像持久化

2026-11-03。用户要求扩展用户表字段并接入微信头像，继续在现有功能分支/PR #13 实施，完成后等待用户 review，不合并或部署。

## 实现方选择

- `chooseAvatar` 由用户主动点击，微信返回本机临时文件路径；客户端通过 wx.uploadFile 上传实际图片，不能把临时路径当成永久地址保存。
- 复用 MySQL 持久化，避免引入对象存储账号或容器本地磁盘依赖：008 新增 `t_users.avatar_url`（ASCII VARCHAR(128)，NULL 默认值、唯一索引）和 `avatar_data`（MEDIUMBLOB，NULL 默认值）。旧用户头像为空，昵称及账单等数据不变。
- 服务端接收不超过 2 MiB 的 JPEG/PNG，先限制尺寸 2048×2048，再解码、中心裁剪和缩放为 256×256 JPEG。仅保存规范化图片，URL 由服务端生成 32 随机字节的不可枚举标识；不接收外部 URL 或客户端用户 ID。

## 接口与权限

- `POST /api/v1/auth/me/avatar`：Bearer 会话，multipart/form-data，只允许单个名为 avatar 的文件；缺昵称用户也可上传。返回当前 `{id,nickname,avatar_url}`。
- `GET /api/v1/avatars/{64位随机hex}.jpg`（含 HEAD）：凭随机地址读取 JPEG，无需 Bearer，便于原生 image 展示；不存在或已替换的旧地址返回 404。除此之外不放开任何业务接口。
- 更新头像在同一行原子更新图片和路径；更换后旧 URL 不再关联图片。不在日志中输出图片/临时路径/完整随机读取地址。
- 登录、GET me、昵称 PATCH 均返回最新 avatar_url；只改昵称不能清空头像，只改头像不能清空昵称。内存模式具有相同语义。
- 头像可选，未选择仍可正常使用；服务端继续要求昵称完成后访问业务。

## 客户端

登录后补昵称表单与设置页“个人资料”展示头像选择按钮及已保存头像；设置页允许更换。上传成功刷新用户缓存，防止旧 me 请求覆盖新资料；失败保留原头像，解除忙状态并提示重试。会话切换后旧上传结果不能污染新账号。

头像路径按当前 API baseURL 展示；退出/切后端清除已显示头像。微信公共平台需将同一 HTTPS API 域名配置为 uploadFile 合法域名。无新增服务端环境变量。
