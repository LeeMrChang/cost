## 方案

使用 Docker Compose，固定项目名 cost-cloud。常驻服务为 api 与 mysql；migrate 为显式执行、执行后退出的一次性任务。api 与 migrate 使用同一后端镜像。

后端采用多阶段构建：Go 构建阶段编译 Linux 二进制，精简 Debian 运行阶段包含 CA 证书，以非 root 用户运行。制作供云服务器使用的 linux/amd64 镜像；构建标签和可拉取性在实施时验证。不能直接把 Mac ARM64 可执行文件放到 Linux。

MySQL 使用 8.4 系列镜像，持久化到独立命名卷；不映射任何宿主机端口。后端通过 mysql:3306 连接，容器内监听 0.0.0.0:8080，宿主机只映射 127.0.0.1:8080。Docker 网络不设置 internal:true，保证 API 能向微信 HTTPS 接口发起请求。

数据库健康检查执行认证后的 SELECT 1，migrate 等数据库健康后运行；API 在显式迁移成功后再启动。不得将容器 running 或 mysqladmin ping 单独当成业务就绪证据。

API 与 MySQL 设置 restart:unless-stopped，日志限额 max-size=10m、max-file=3。停止和重建容器保留命名卷；运维命令不包含 down -v。数据库备份输出到容器之外，并提供独立测试库恢复验证方法；数据卷不是备份。

## 配置与权限

云端目录为 /home/ubuntu/cost，部署命令从其中的 deploy/ 执行。Compose 文件名 compose.cloud.yaml，示例配置 .env.example，真实配置 .env 权限 600。部署包排除真实 .env、本机二进制、Git 元数据、数据库备份和小程序代码。

云端使用全新随机 MySQL root 与业务密码及初始化密钥，推荐 openssl rand -hex 32 生成，避免 DSN 特殊字符编码问题。微信 AppID 使用现有小程序，AppSecret 只在云端配置。production 模式强制 mysql 与 wechat。

迁移账号与运行账号分离：数据库初始化脚本创建具有本库 DDL 权限的 cost_migrator；业务账号仅 SELECT、INSERT、UPDATE、DELETE。必须以空数据卷验证初始化脚本，不能假定其在已有数据卷上自动重跑。根密码不进入 API 容器。

首次云端迁移创建默认账本和分类，账单、预算、用户和成员为空。用户通过真实微信登录后以云端初始化密钥绑定管理员；Mac 中的登录状态及初始化密钥不复制到云端。

## 上传与无域名联调

本地生成最小部署包，通过 scp 上传到 ubuntu@公网IP:/home/ubuntu/cost/。不依赖 GitHub 推送；本机尚未审阅的更改不被自动提交或上传。

服务器安装 Docker 后按文档顺序完成：解包、填写私有配置、构建镜像、启动数据库并等待健康、运行显式迁移、启动 API、检查日志及健康、验证重启后数据保留。

Mac 使用 ssh -N -L 18080:127.0.0.1:8080 ubuntu@公网IP 建立隧道，开发者工具请求 http://127.0.0.1:18080；不占用 Mac 已有 8080。此方法用于 Mac 模拟器，不意味着手机可使用手机自己的回环地址访问云端。

当前仅内部部署，不开放 8080/3306。增加可选 https profile，默认 api.xiachen.xyz，使用 Caddy 转发到 API。接入备案、DNS 和 80/443 满足后才启用；不自动发布小程序。

## 验收

- 部署包没有密钥、已有账单或其他未提交小程序改动。
- Compose 必填配置缺失即失败；私有配置不出现在分享日志中。
- 隔离空测试卷上迁移首次成功、重复成功；账单数量为零，默认分类存在。
- 业务账号可运行登录和记账接口，但不能创建/删除表。
- 8080 仅绑定回环地址，MySQL 无宿主机端口；微信请求可出站。
- API/数据库健康、日志有界，重建后测试记录保留，备份可在独立测试环境恢复。
- 本地自动检查和实际云端操作分别记录；未在真实服务器执行的步骤明确标为待验证。
