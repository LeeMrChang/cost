# 账本资料编辑与昵称复用

2026-11-03。用户要求设置页顶部“我的账本”可编辑，并询问登录页自动带入昵称和其他微信资料的能力；延续用户已明确的直接在功能分支实施方式，不新增审批关卡。

## 设计

- 首次进入且无有效会话不能直接获得微信昵称；由用户点击微信登录后验证身份，从服务端复用该账号已存昵称。已有昵称直接进入账本，缺昵称显示填写表单，仍需完成昵称后才可访问业务。有效会话仍直接读取资料；不跨账号预填昵称。
- 补填期间会话过期时重新微信认证；确认用户 ID 相同才继续保存草稿，身份改变则清空旧草稿，为新身份重新填写。
- 不增加头像或手机号采集；头像可以通过用户主动选择另行接入，当前只说明能力。
- 设置页顶部账本卡片增加编辑入口，展开名称表单与图标选项，保存/取消。保存失败保留草稿，取消不发请求。昵称仍使用已有资料表单修改，不混同账本名称与用户昵称。
- 新增 `PATCH /api/v1/ledgers/me`，仅接收 name/icon 的部分更新。服务端会话绑定账本，拒绝额外 id/owner_id/currency/timezone 字段。名称去首尾空白后 1–64 个 Unicode 码点，图标 1–32 个，拒绝控制/行分隔字符和非法 UTF-8。空更新无效。
- 内存和 MySQL 更新当前上下文账本的对应字段；不改账单、账户、分类、币种或时区。使用已有 name/icon 列，不新增迁移。首页返回时原有 onShow 读取最新账本即可同步展示。
- 图标界面提供固定常用 emoji 选项，保留已有图标未选择时的值。名称最大 128 个 UTF-16 单元并按 64 码点校验，支持 emoji。

## 验收

HTTP 流程验证认证、name/icon 保存、部分更新、Unicode 边界、空白与额外字段拒绝、不同用户隔离及失败不覆盖。编写隔离 MySQL 相同流程测试；真实数据库测试沿用上一任务的环境限制，不操作业务库。

页面测试覆盖编辑预填、取消不写入、保存/失败重试、空名拒绝、回首页加载新值；登录覆盖新用户补填、老用户无会话登录自动复用、已有会话直接进入。Go race/vet/build、Node 全套、页面检查；独立审查。微信开发者工具与真机未运行时明确记录。
