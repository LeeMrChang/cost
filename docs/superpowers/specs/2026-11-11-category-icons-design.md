# 分类候选图标接入设计

来源：用户指定的本地 `cost分类图标候选对照.html`。用户授权加入候选图标并覆盖现有对应图标。

## 范围与验收

采用绿框建议：福利 🎫、奖金 🏆、副业 🌱、加班 ⏰、早餐 🥐、午餐 🍛、晚餐 🍲、夜宵 🍗、消费 🛒、其他（支出）📦。其余 14 个默认分类保持不变。所有备选 Emoji 加入分类编辑器，已有可选图标保留、去重。不新增文件中不存在的分类或外部图片依赖。

后端 DefaultCategories 使用建议图标，使内存模式和新账本一致。已有账本通过 009_category_icons.sql 更新：仅 ledger_id=1、匹配名称和收支类型的 10 类，按用户要求覆盖现有图标（包括这些分类的自定义图标）。保留分类 ID、名称、排序、停用状态、父分类和账单关联；不插入或删除分类，不匹配改名后的分类，不触及其他账本。

## 数据、接口与权限

继续使用现有 icon 字符串字段和分类 PATCH 接口，无新权限、接口或结构列。迁移在事务中执行图标更新与版本标记，重复执行已标记迁移不覆盖后续用户编辑；失败回滚可重试。实际账本升级前必须备份；本次只对随机隔离测试数据库运行迁移。

## 验证与风险

先验证默认图标、候选选择保存及旧数据迁移的失败测试，再实现。运行前端全量测试、语法检查、Go race/vet/build，并使用隔离 MySQL 覆盖旧数据保留、按收支区分、范围限制和重复迁移。微信 Emoji 外观因系统不同存在差异，开发者工具与真机未执行时明确记录。部署迁移后重启服务以更新分类缓存。

## 流程说明

设计在实现前记录。当前环境此前检索未找到 using-superpowers、brainstorming、writing-plans 等技能，不能声称完整执行这些技能；用户已明确覆盖要求，由当前代理执行，没有独立审查或单独设计批准证据。
