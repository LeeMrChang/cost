# Cost Redis 分类与账本资料缓存

用户明确：当前并不明显卡顿，目标是让已部署的 Redis 实际被 Cost 使用。本轮不再以耗时采样作为接入前提。沿用 `infra/redis-homepage-diagnostics` 和 PR #15 交付，保留用户 review 后合并。

## 范围与实施者选择

仅缓存认证完成后的 `GET /api/v1/categories`、`GET /api/v1/ledgers/me` 成功结果，TTL 固定 300 秒。分类用于创建/编辑账单的服务端校验仍直接查询数据库；认证、会话、用户头像、账单、金额统计、余额与预算均不缓存。不改变小程序或数据库结构。

使用固定 `github.com/redis/go-redis/v9 v9.17.3`（其模块要求 Go 1.18，兼容仓库 Go 1.23），小连接池、禁用重试、显式连接/读写/池等待和上下文期限。配置 `COST_REDIS_ADDR` 与 `COST_REDIS_PASSWORD`；地址为空禁用，两者不完整时启动拒绝但不输出值；迁移进程不需要 Redis。配置完整而 Redis 不可达时 API 仍启动，读取/填充失败均回退原数据库响应。

缓存失败边界每次最多 80 ms；失败读不再尝试写缓存。暴露两个资料接口的 `X-Cost-Cache: HIT|MISS|BYPASS` 响应头便于验收，不暴露凭证、键或用户信息；Redis 不是健康检查的硬依赖。

## 隔离、并发与失效

现有部署只有一个 API 容器，本文明确以单 API 进程写入为边界。每个 handler 实例生成随机启动命名空间，键包括命名空间、原子代次、账本 ID、资料类型。分类新增/编辑/排序/启停与账本资料修改成功后、返回响应前推进代次；确定未写入的验证/冲突错误不推进；内部错误、回读失败或提交结果不确定时保守推进，避免已提交的新值被旧缓存遮蔽。所有旧代次被即时逻辑失效，旧键由 300 秒 TTL 回收，不依赖 Redis DEL 的成功，故断线期间修改、重连后的旧值也不会再读。并发旧读在 SQL 查询前固定代次，之后只能填充旧键，不能污染修改后的新键。冷启动使用全新命名空间，避免前次运行的旧值。

代次针对全部资料缓存一起推进，资料修改频率低，这样比维护每用户的锁/状态更简单。正在写入完成前开始的读可以看到此前快照，后续读必须看到新资料。只接受对应 Go 类型的有效 JSON；错误响应不缓存，缓存无效则查 SQL 并修复。

不支持多个 API 进程同时修改相同数据库后互相实时失效；横向扩容前必须改为共享代次或可靠失效事件。本轮不增加集群复杂度。手工 SQL/离线工具修改资料后应重启 API 立即清缓存，否则最长 300 秒可见。Redis 只是可丢失结果缓存。

## 部署与验收

云端 Compose 给 API 注入可选的两项环境变量；不将 Redis 并入 Cost compose 或重启 Redis。提供服务器一次性配置脚本，从已有 `/home/ubuntu/cost/redis/.env` 严格读取密码，将两项配置写入既有 `/home/ubuntu/cost/deploy/.env`，保留其他值并设为 600，不打印密码，不重启服务。须在合并后端接入代码之前执行，下一次正常 CI/CD 部署后启用。关闭时清空这两项再重启/重建 API，不动 MySQL。

测试先证明：第二次读取减少底层读取；按账本/实例隔离；成功修改立即更新、失败修改不驱逐；并发旧读及断线期间修改不能回填旧值；缓存损坏/不可达/慢响应回退；未登录/失效会话不能读缓存；配置不泄密。真实 Redis 集成测试在既有 GitHub 隔离 smoke 运行，覆盖认证、GET/SET/TTL，生产部署与实际命中仍需用户执行和截图验收。
