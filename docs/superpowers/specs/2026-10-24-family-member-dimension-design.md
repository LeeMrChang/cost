# F05 家庭成员维度设计

日期：2026-10-24。状态：用户已于本会话确认执行，本地实现及自动化验证已完成，真机与生产启用尚待执行。本文基于现有 F01–F04 实现补充需求。

## 目标与方案选择

让家人能识别记录人，用“全家 / 我的 / 指定成员”查看同一范围的账单和汇总，并在成员移除后保留历史可识别性。

推荐：成员维护自己的昵称，管理员也可修改当前成员昵称；全部记录按成员的最新昵称显示。备选一是仅管理员维护，维护简单但成员不能自行设置；备选二是每笔账单保存昵称快照，能保留当时名称，但改名后展示不一致并增加数据冗余。首版采用推荐方案，具体规则已由用户确认。

## 范围与统计口径

- “成员维度”只表示谁录入账单，依据不可由客户端冒充的 created_by；不等于付款人、实际消费者或费用归属人。
- 保持单部署单家庭、共享账本，普通成员只能修改自己的账单，管理员可管理全部记录。
- 增加昵称设置、列表与筛选中的名称展示、“全家 / 我的”快捷入口，以及已移除成员和未指定创建人的历史展示。
- 成员筛选继续与日期、分类、金额、账户、关键词共同生效；总笔数、收入、支出、结余使用分页前的全部匹配记录。转账不计入这些收支汇总。
- “全家”只清除成员条件，“我的”将成员条件设为当前登录用户 ID；两者均保留其他筛选条件并重置分页。清空全部筛选仍使用现有行为。
- 不新增成员排行、多人对比图、个人私密账本或微信头像/昵称自动获取。

## 昵称与权限

- 昵称去除首尾 Unicode 空白及 BOM，允许中文、英文和 emoji；非空时为 1–20 个 Unicode 码点，拒绝换行和控制字符。允许显式空字符串清除昵称，显示回退为“成员 ID”。
- 昵称可重复；成员选项与管理列表同时展示编号以区分重名，权限和筛选始终使用 ID。
- 当前家庭成员可修改自己的昵称；管理员还可修改其他当前成员昵称。普通成员修改他人、未加入成员或已移除成员调用写接口均拒绝。
- 管理员不能通过本接口修改角色、成员 ID 或记录归属；对已移除成员不提供昵称修改入口。
- 改名后历史账单显示最新昵称，不改变创建人和账单内容。
- 移除成员只撤销访问权，保留用户昵称、创建人 ID 和账单；再次加入后恢复当前成员展示。

## 数据模型与接口

- 增加显式 `005_member_nicknames.sql` 迁移，为 t_users 增加 nickname（VARCHAR(80)，utf8mb4，NOT NULL，默认空字符串，中文字段注释）；应用层限制 20 个码点。保留已有数据，遵循现有迁移重试规则。
- 登录、GET /api/v1/auth/me、现有管理员成员列表在原字段基础上增加 nickname；保持 id、role 含义兼容。
- 新增 PATCH /api/v1/family/members/{id}/nickname，正文为 {nickname:string}。必须明确提交 nickname，禁止未知字段及 null；成功返回更新后的 id、nickname。未登录 401，非家庭成员或无修改权限 403，非法昵称/请求 400，管理员操作不存在或已移除对象返回 404。
- GET /api/v1/entry-authors 保留数组结构及 id，增加 nickname 和 status。status 为 active、removed、unspecified。返回当前成员与历史账单/转账创建人的并集，按 ID 排序；仅在有无创建者历史账单或转账时包含 id=0。
- 成员目录只允许有家庭访问权的用户读取，不暴露 openid、会话或微信身份原文。历史成员仅包含当前账本已有收支或转账记录引用的创建人。
- 成员资料由认证仓储读取，业务记录仓储继续负责历史创建人 ID；接口层合并目录，内存实现与 MySQL 实现保持一致。
- CSV 保留现有记录人 ID 列，追加记录人名称与状态列；沿用中文编码、转义与公式注入防护。名称展示与账本保持一致。

## 页面与交互

- 设置页提供“我的昵称”编辑、保存、清除和错误提示；管理员在现有成员列表中可编辑当前成员昵称。
- 账本页增加“全家 / 我的”快捷筛选，并与高级筛选的指定成员选择同步；切换后重新查询，不混入旧分页数据。
- 账单、成员筛选与 CSV 使用一致名称：有昵称显示昵称，无昵称显示“成员 ID”；已移除成员附“已移除”标识；创建人为 0 显示“历史未指定成员”。
- 转账列表如展示创建人，应复用相同的名称回退规则；不增加转账成员统计。
- 保存昵称后刷新自身会话资料和当前成员列表；账本重新进入时读取最新目录。保存期间禁用重复提交，失败保留用户输入。
- 账号切换、退出、家庭权限失效时清理成员资料，沿用现有会话失效流程。

## 验收与验证

1. 成员设置中文/emoji 昵称后，重新登录、账单展示、成员筛选和 CSV 显示一致；旧记录仍归属原 ID。
2. 空昵称回退正确；20 码点通过，21 码点、换行、控制字符、null 与缺字段被拒绝；重名仍能按编号区分。
3. 普通成员只能改自己的昵称；管理员可修改当前成员；未加入、已移除、匿名用户不能修改或读取家庭目录。
4. “我的”仅筛选当前 ID，“全家”保留其他条件；指定成员、日期和金额组合筛选的列表、笔数、合计、CSV 一致，分页不漏不重复。
5. 无账单的新成员出现在筛选目录；无匹配记录时显示零笔及零汇总。
6. 移除成员后该成员无法访问家庭，但历史记录和昵称仍可见且标明已移除；历史 created_by=0 明确标识；重新加入后标识恢复。
7. 迁移前旧用户、成员、账单数量与金额保持不变；验证迁移重复执行及重试行为。
8. 先执行失败测试，再实现：Go 权限/昵称/目录测试、隔离 MySQL 迁移与历史保留测试、前端昵称与筛选测试、CSV 防注入回归测试。
9. 完成后执行 Go race/vet/build、全部前端检查及相关备份恢复校验；如新增迁移影响恢复版本检查，同步更新。真机、多人真实微信与文件分享单独记录，不以自动化测试代替。

## 风险与发布边界

- 昵称是用户填写的展示文本，不能作为身份或权限凭据；CSV 对新增名称列同样处理公式前缀。
- 真实数据库升级前必须备份；开发和集成测试仅使用独立测试数据库。
- 本次实现范围为本地代码、测试和文档；云端迁移、部署、小程序上传发布另行执行。
