# F05 家庭成员昵称与筛选 API

2026-10-24。成员表示记录人，身份与权限依据 ID 和当前家庭角色，昵称仅用于展示。全部业务接口沿用 Bearer 会话认证。

## 修改昵称

`PATCH /api/v1/family/members/{id}/nickname`

```json
{"nickname":"妈妈🍀"}
```

普通成员只可修改自己；管理员可修改其他当前家庭成员。已移除成员不可修改，不能修改角色或记录归属。

昵称必须是明确提交的字符串，空字符串可清除；裁剪首尾 Unicode 空白与 BOM 后最多20个 Unicode 码点，拒绝控制字符、换行、null、字段省略及未知字段。名称可重复，界面同时展示编号以区分。成功返回 `{id,nickname}`；400 为非法请求/昵称，401 未登录，403 无权限或无家庭访问权，404 目标不是当前成员。

写入在内存锁或数据库事务内重新核实操作者和目标成员关系。改名后历史记录显示最新昵称；移除成员保留用户资料和历史记录。

## 登录及成员资料

登录响应的 user、`GET /api/v1/auth/me`、管理员的 `GET /api/v1/family/members` 在 id、role 基础上增加 nickname。未设置时为 `""`，展示回退为“成员 ID”。客户端保存后重新读取资料；切换账号后丢弃旧账号迟到响应，不覆盖新会话资料或因旧401/403清除新会话。

`GET /api/v1/entry-authors` 返回按 ID 排序的数组：

```json
[{"id":0,"nickname":"","status":"unspecified"},{"id":2,"nickname":"妈妈🍀","status":"active"}]
```

目录包含当前成员（即使没有账单）与本账本收支/转账引用的历史创建人。status 为 active（当前）、removed（已移除）、unspecified（历史未指定）；仅有无创建人记录时包含 id=0。目录不暴露微信 OpenID 或会话。已移除成员显示“昵称（已移除）”，再次加入恢复 active。

## 筛选与 CSV

“全家”只清除 created_by；“我的”设置为当前成员 ID；指定成员仍使用 created_by。保留其他筛选条件，切换后从第一页加载。笔数、收入、支出、结余按全部匹配记录计算，转账不进入收支汇总。

CSV 保留原8列，追加“记录人名称”“成员状态”。名称与账单显示一致；状态为“在家成员”“已移除”“历史未指定成员”。新增名称同样进行公式注入防护；编号列不改变。

## 迁移

先备份业务库，再通过现有迁移命令应用 `005_member_nicknames.sql`，之后启动新版服务。迁移为 t_users 增加 nickname，旧用户默认空字符串；DDL中断重试不覆盖已有昵称。备份恢复校验新增005版本及昵称列可查询性检查。
