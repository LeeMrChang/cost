# 审核登录生产接口修复验证

## 现象和定位

微信反馈安卓 Wi-Fi 环境在登录页无法继续，截图出现本地调试地址。旧实现只根据 envVersion=develop 选择本地默认接口。这个条件也会用于手机开发预览，不能保证审核/预览设备能访问后端。尚无审核设备的环境元数据、请求日志或当时上传包，不能断言审核 envVersion 的具体值。

设计见 [修复设计](../superpowers/specs/2026-11-13-review-production-backend-design.md)。开发者工具开发版现在默认本地，其余环境默认生产 HTTPS；只有开发者工具开发版允许显式覆盖，手机忽略本地调试缓存并隐藏调试表单。旧 cost_base_url 缓存已停用，工具调试改用 cost_devtools_base_url。

## 测试与网络证据

- 修复前：新增环境测试 7 项失败、登录页测试 4 项失败；断言显示实际使用回环地址，而期望生产 HTTPS，或手机调试入口未隐藏。
- 后续补测：旧开发工具缓存覆盖默认地址的断言失败，再改为独立调试缓存键；显式本地覆盖的测试随新键同步更新。
- 测试命令：`node --test miniprogram/tests/*.test.js`。
- 页面与语法检查：`node miniprogram/tests/validate.js`。
- 2026-11-13 公网只读访问（本机直连、未使用 HTTP 代理）：`GET https://api.xiachen.xyz/health` 返回 200，TLS 校验结果 0，JSON 的 status=ok、auth_mode=wechat；未登录 GET /api/v1/auth/me 返回预期 401。没有调用真实登录，也没有读写账单。

最终结果：147 项小程序测试全部通过（0 失败、0 跳过），JavaScript 语法、JSON 与页面文件检查通过，git diff --check 通过。健康检查和 401 只能证明当前 Mac 的公网路径与 API 可达，不能证明微信合法域名、审核网络或真实登录已通过。

## 重新上传前的验收

1. 微信开发者工具打开仓库的 miniprogram/，重新编译。开发者工具开发版默认连接应为 http://127.0.0.1:8081；体验/正式版和手机应为 https://api.xiachen.xyz，不能沿用本地目录里的旧上传包。
2. 微信公众平台核对 request 合法域名为 https://api.xiachen.xyz；若使用头像上传，核对 uploadFile 合法域名也包含同一域名。
3. 在开发者工具开启域名、TLS 与证书校验，使用体验版/手机预览验证。真实手机不应出现“开发环境连接”。
4. 用安卓真机测试 Wi-Fi 和移动网络：首次微信登录、填写昵称、进入账本，按个人意愿新建测试账单后删除。不要把模拟器编译或健康接口成功等同于这些场景已通过。
5. 录制完整核心流程，上传新版本；在提审页面附录屏并说明已修复默认后端地址问题，再提交审核。以微信后台实际审核结果为准。

## 本地开发默认值调整

按用户确认，开发者工具中的开发版应默认连接本地。先运行对应断言，观察两项失败（实际生产 HTTPS，期望本地地址），再恢复 developmentBaseURL，保留设备平台限制和旧缓存隔离。当前 backend/.env 的 COST_ADDR 为 0.0.0.0:8081，故默认使用 http://127.0.0.1:8081；127.0.0.1 与 localhost 在此均指本机。真实手机、体验版和正式版继续自动使用生产 HTTPS。新增登录页本地默认显示断言后，完整 147 项测试通过。
